# 📋 requirements/ — 要件定義書

## 役割

新機能・追加開発の**要件定義書**を格納するディレクトリです。  
`/requirements` スキルによって自動生成されます。

> 保守・バグ・軽微なエンハンスは `docs/maintenance/` に格納します。

## ファイル命名規則

```
{機能名}.md
例: user-authentication.md / product-search.md
```

## 記載すべき内容

| 項目 | 内容 |
| --- | --- |
| **概要** | なぜこの機能が必要か（目的・背景） |
| **ユーザーストーリー** | 「〜として、〜したい。なぜなら〜だから。」の形式で |
| **機能要件** | 何を実現するか。受け入れ条件（Acceptance Criteria）付きで |
| **非機能要件** | パフォーマンス・セキュリティ・スケーラビリティなど |
| **画面一覧** | 関連する画面の概要リスト |
| **API一覧** | 関連する API エンドポイントの概要リスト |
| **スコープ外** | 今回対応しないことの明示 |

## テンプレート

```markdown
# {機能名}

## 概要

<!-- なぜこの機能が必要か -->

## ユーザーストーリー

- {アクター}として、{目的}がしたい。なぜなら{理由}だから。

## 機能要件

### {機能1}
- 受け入れ条件:
  - [ ] ...

## 非機能要件

- パフォーマンス: ...
- セキュリティ: ...

## 画面一覧

| 画面名 | 概要 |
| --- | --- |

## API一覧

| エンドポイント | メソッド | 概要 |
| --- | --- | --- |

## スコープ外

- ...
```

