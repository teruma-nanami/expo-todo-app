# 🔧 maintenance/ — 保守運用ドキュメント

## 役割

バグ修正・軽微なエンハンス・調査タスクなど、**保守運用に関する要件定義書**を格納するディレクトリです。  
`/requirements` スキル（保守運用パターン）によって自動生成されます。

> 新機能・大きな追加開発の要件は `docs/requirements/` に格納します。

## ファイル命名規則

```
{ID}-{内容のkebab-case}.md
例: 42-fix-login-redirect.md / 55-improve-search-performance.md
```

- `{ID}` は対応する GitHub Issue 番号
- `{内容}` は英語 kebab-case で簡潔に

## 記載すべき内容

| 項目 | 内容 |
| --- | --- |
| **概要** | 何を・なぜ対応するか（1〜2文） |
| **背景・発生状況** | いつ・どこで・どのように問題が起きているか |
| **対応内容** | 具体的に何を修正・変更するか |
| **影響範囲** | 変更によって影響を受ける機能・画面・API |
| **完了条件** | 何が揃えば対応完了とみなすか（チェックリスト形式） |
| **関連リンク** | Issue URL / エラーログ / Slack スレッドなど |

