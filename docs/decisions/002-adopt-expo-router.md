# 002: Expo Router の採用

**ステータス:** 採用  
**決定日:** 2026-06-02

## コンテキスト

複数画面（一覧・追加/編集）を持つアプリを構築するため、ナビゲーションライブラリを選定する必要があった。React Native のナビゲーションは `react-navigation` が事実上の標準だが、Expo エコシステム内で完結させる選択肢として Expo Router がある。

## 決定内容

Expo Router（ファイルベースルーティング）を採用する。

## 理由

- **ファイル配置＝ルート定義**: `app/` ディレクトリ内のファイル構成がそのまま画面遷移に対応するため、ルーターの設定コードが不要。
- **Next.js との概念的一致**: Web フロントエンドに慣れた開発者が移行しやすく、ポートフォリオとしての説明コストが低い。
- **Expo 公式サポート**: Expo SDK と連携して動作保証されており、個別バージョン管理が不要。
- **型安全なナビゲーション**: TypeScript との統合が良好で、画面遷移パラメーターに型が付く。

## 検討した代替案

| 案 | 却下理由 |
| --- | --- |
| react-navigation | 設定ファイルに Navigator / Screen の宣言が必要で、画面が増えるほど管理コストが上がる。 |
| 独自実装（useState での画面切り替え） | スタック遷移・戻るボタン対応などを自前で実装する必要があり、過剰な工数がかかる。 |

## 影響・トレードオフ

- Expo Router は Expo に強く依存するため、bare workflow への移行時に再実装が必要になる。
- `app/` ディレクトリ外のファイルはルートにならないため、ファイル配置のルールを守る必要がある。
