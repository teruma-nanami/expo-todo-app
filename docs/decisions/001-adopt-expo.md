# 001: Expo の採用

**ステータス:** 採用  
**決定日:** 2026-06-02

## コンテキスト

React Native アプリを開発するにあたり、ビルドツールチェーン・開発サーバー・デバイスプレビューをどう用意するかを決める必要があった。ネイティブ SDK の設定や Xcode / Android Studio との統合は複雑で、学習コストが高い。

## 決定内容

Expo（Managed Workflow）を採用する。

## 理由

- **環境構築コストが低い**: `npx create-expo-app` 一コマンドで動く雛形が得られ、Xcode・Android Studio のフルセットアップが不要。
- **Expo Go でのリアルタイムプレビュー**: 実機・シミュレーターへの即時反映が可能で、開発サイクルが速い。
- **エコシステムの充実**: Expo Router・Expo SecureStore など、公式ライブラリが揃っており追加の設定なしで利用できる。
- **ポートフォリオ目的に適合**: 成果物をすぐに動かして見せられることが転職活動上のメリットになる。

## 検討した代替案

| 案 | 却下理由 |
| --- | --- |
| React Native CLI（bare workflow） | Xcode / Android Studio のセットアップが必要で初期コストが大きい。ポートフォリオ用途では過剰。 |
| Flutter | Dart 言語の学習コストが高く、React / TypeScript スキルのアピールという目的に合わない。 |

## 影響・トレードオフ

- Expo が対応していないネイティブモジュールは使いにくい（Managed Workflow の制約）。
- EAS Build を使わないとネイティブビルドの細かい制御ができない。
- Expo SDK のバージョンアップに追従する必要がある。
