# 🏛️ decisions/ — アーキテクチャ決定記録（ADR）

## 役割

プロジェクトの重要な技術的意思決定とその背景・理由を記録する **ADR（Architecture Decision Record）** を格納するディレクトリです。

「なぜこのアーキテクチャを選んだのか」を後から辿れるようにするための記録です。コードを読んでも分からない「判断の理由」を残します。

## いつ書くか

以下のような意思決定をした際に作成します。

- フレームワーク・ライブラリの選定（例: なぜ HeroUI を選んだか）
- アーキテクチャパターンの採用（例: Repository パターンを採用した理由）
- 技術負債の意図的な積み増し（例: 今は妥協するが後で直す）
- 却下した代替案とその理由
- 外部サービスの選定（例: 認証に Firebase ではなく Sanctum を使う理由）

## ファイル命名規則

```
{連番}-{タイトルのkebab-case}.md
例: 001-use-repository-pattern.md / 002-adopt-heroui.md
```

## 記載すべき内容

| 項目 | 内容 |
| --- | --- |
| **ステータス** | 提案中 / 採用 / 却下 / 廃止 |
| **コンテキスト** | なぜこの決定が必要になったか（背景・課題） |
| **決定内容** | 何を選んだか |
| **理由** | なぜそれを選んだか |
| **代替案** | 検討した他の選択肢とその却下理由 |
| **影響** | この決定によって生じるトレードオフ・制約 |

## テンプレート

```markdown
# {連番}: {タイトル}

**ステータス:** 採用 / 提案中 / 却下 / 廃止  
**決定日:** YYYY-MM-DD

## コンテキスト

<!-- なぜこの決定が必要になったか。どんな課題・制約があったか -->

## 決定内容

<!-- 何を選択したか、一文で明確に -->

## 理由

<!-- なぜその選択をしたか。技術的・ビジネス的な根拠 -->

## 検討した代替案

| 案 | 却下理由 |
| --- | --- |
| 案A | ... |
| 案B | ... |

## 影響・トレードオフ

<!-- この決定によって生じる制約・リスク・将来の課題 -->

## 関連リンク

- ...
```
