# 📚 reference/ — 参照資料

## 役割

開発・運用で参照する**技術資料・調査結果・外部ドキュメントへのリンク集**を格納するディレクトリです。

仕様決定の根拠となった調査や、チームで共有すべき技術的知識を記録します。

## ファイル命名規則

```
{トピック}.md
例: coding-conventions.md / performance-benchmarks.md / third-party-licenses.md
```

## 記載すべき内容

| ファイル例 | 記載内容 |
| --- | --- |
| `coding-conventions.md` | コーディング規約の補足・例外ルール・判断基準 |
| `environment-setup.md` | ローカル開発環境のセットアップ手順 |
| `performance-benchmarks.md` | 負荷テスト結果・パフォーマンス計測値の記録 |
| `security-checklist.md` | リリース前のセキュリティ確認項目 |
| `investigation-{テーマ}.md` | 技術選定・調査のまとめ |
| `glossary.md` | プロジェクト固有の用語集・ドメイン用語の定義 |

## 記載の基本フォーマット

```markdown
# {タイトル}

**作成日:** YYYY-MM-DD  
**更新日:** YYYY-MM-DD  
**作成者:** @{GitHub ユーザー名}

## 概要

<!-- この資料の目的・読むべき人 -->

## 内容

<!-- 本文 -->

## 参考リンク

- [タイトル](URL)
```

## 調査メモの書き方

技術選定・ライブラリ比較などの調査結果は以下の形式を推奨します。

```markdown
# 調査: {テーマ}

## 背景・調査目的

## 比較した選択肢

| 項目 | 選択肢A | 選択肢B | 選択肢C |
| --- | --- | --- | --- |
| 特徴 | ... | ... | ... |
| 採用実績 | ... | ... | ... |
| ライセンス | ... | ... | ... |

## 結論

**採用:** {選択肢名}  
**理由:** ...

## 参考リンク
```

> 調査結果をもとに意思決定をした場合は `docs/decisions/` にも ADR として記録してください。
