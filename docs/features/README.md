# 🖥️ features/ — 機能設計書

## 役割

要件定義をもとに作成した**機能設計書**を格納するディレクトリです。  
`/feature-design` スキルによって自動生成されます。

## ファイル命名規則

```
{機能名}.md
例: user-authentication.md / product-search.md
（requirements/ と対応するファイル名にする）
```

## 記載すべき内容

| 項目 | 内容 |
| --- | --- |
| **機能一覧** | アクター・画面・概要を表形式で |
| **画面フロー** | Mermaid フローチャートで遷移を視覚化 |
| **状態遷移** | Mermaid stateDiagram でリソースの状態変化を視覚化（該当する場合のみ） |
| **ビジネスルール** | 条件・結果・違反時の挙動を表形式で |
| **サーバー境界図** | Server / Client Component の配置と責務の分離 |
| **認証・認可設計** | middleware / layout / page の3層でどこで何を弾くか |
| **画面・API マッピング** | 画面の操作とAPIエンドポイントの対応表 |
| **付録: 設計レビュー結果** | SEC / PERF / ARCH / UX 観点のセルフチェック結果 |

## テンプレート

```markdown
# {機能名} 機能設計

## 機能一覧

| # | 機能名 | アクター | 概要 | 対応画面 |

\`\`\`mermaid
flowchart TD
  A[画面A] --> B[画面B]
\`\`\`

\`\`\`mermaid
stateDiagram-v2
  [*] --> 下書き
  下書き --> 公開
\`\`\`

## ビジネスルール

| # | ルール | 条件 | 結果 | 違反時の挙動 |
| --- | --- | --- | --- | --- |

## サーバー境界図

\`\`\`
page.tsx (Server)
  └─ ComponentA (Server)
       └─ ComponentB (Client: useXxx)
\`\`\`

## 認証・認可設計

| 層 | チェック内容 | 失敗時の挙動 |
| --- | --- | --- |
| middleware.ts | 未認証リダイレクト | /login |
| layout.tsx | 権限確認 | 403 or / へ redirect |
| page.tsx | リソース所有権 | 404 or 403 |
```
