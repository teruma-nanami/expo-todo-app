# 🎫 issue — GitHub Issue 作成

要件定義をもとに GitHub Issue を作成するスキル。新規開発・追加開発・保守運用の3パターンに対応。

## 使い方

```
/issue
```

「Issue作成」「Issueを作りたい」「チケットを切りたい」でも起動。

## パイプライン

```
前提: /requirements 完了
読込: docs/requirements/ / docs/features/（新規・追加）
      docs/maintenance/（保守運用）
出力: GitHub Issue
```

## パターン別の粒度

| パターン | 目安 | Issue 粒度 |
| --- | --- | --- |
| 新規開発 | 設計フェーズが必要な新機能 | 機能単位で複数 Issue |
| 追加開発 | 既存機能への大きめの追加 | 1〜複数 Issue |
| 保守・バグ・エンハンス | 設計不要〜軽微な改善 | 1 Issue = 1チケット |

## プロセス

1. 要件定義ドキュメントを読込
2. パターン確認（対話で規模感を判断）
3. Issue 内容を整理（概要・対応内容・関連ファイル・工数見積もり）→ 承認
4. **工数・納期をユーザーと対話で決定**（未定のまま作成しない）
5. `gh issue create` で作成
6. Issue 番号確定後にブランチ名を最終確定

## ルール

- 承認なしに Issue を作成しない
- 工数は h 単位で内訳付きで見積もる
- **納期（着手・完了予定日）は必ず対話で決定する**
- ブランチ名は CLAUDE.md の規約に準拠: `<type>/#<Issue番号>-<kebab-case>`
