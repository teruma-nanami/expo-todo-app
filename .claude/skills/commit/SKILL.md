# コミット

CLAUDE.md の Git 規約に沿ってコミットを作成する。format / lint / typecheck を自動実行してから提案する。

## プロセス

### 1. ブランチと変更内容の確認

1. `git status` と `git diff --name-only` で変更ファイル一覧を取得、`git diff --stat` で規模を把握
2. 現在のブランチが `main` または `develop` でないことを確認
   - 保護ブランチの場合は `/branch` を案内してブランチ作成を提案する

### 2. 差分種別の判定と自動チェック

変更ファイル一覧から影響範囲を判定し、該当するチェックを **自動実行** する（ユーザーの確認なしで良い）。

| 差分                                            | 実行コマンド                | 失敗時の扱い                                                                                                              |
| ----------------------------------------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `backend/**/*.php` を含む                       | `make pint`                 | 自動整形結果をステージに含める                                                                                            |
| `frontend/**/*.{ts,tsx,js,jsx,json,css}` を含む | `make format` → `make lint` | 自動整形結果をステージに含める。lint エラーは `make lintfix` で自動修正を試み、残るエラーはユーザーに通知してコミット中断 |
| `frontend/**/*.{ts,tsx}` を含む                 | `make typecheck`            | 型エラーは必ず通知し、コミット中断                                                                                        |

**ルール:**

- format は自動修正して再ステージ（ユーザー手を止めない）
- lint / typecheck の **エラー**（warning は除く）は修正してからコミット
- 自動修正で `pre-commit` 前に既に CI 水準に乗せる（今回のようにフォーマット忘れで CI が落ちるのを防ぐ）

### 3. コミットメッセージの提案

1. 変更内容を分析し、適切な type を選択:
   - feat / fix / refactor / docs / style / test / chore / hotfix
2. コミットメッセージを提案し、ユーザーの承認を得る
   - 複数の論理的変更が混ざっている場合は、分割コミットを提案する

### 4. コミット実行

承認後にコミットを実行する。HEREDOC でメッセージを渡し、末尾に `Co-Authored-By: Claude <noreply@anthropic.com>` を付ける。

## ルール

- コミットメッセージ形式: `<type>: <概要>`
- 概要は日本語で簡潔に
- 機密ファイル（.env, .pem, .key, .secret）をステージしない
- 承認なしにコミットしない（自動チェックは承認不要、コミット実行は承認必須）
- 型エラー・lint エラーが残っている状態でコミットしない
- format の自動修正は通知のみでユーザーの手を止めない

## Troubleshooting

Error: `make format` / `make lint` が失敗
Cause: docker コンテナが起動していない
Solution: `make up` を案内する。起動後に再実行

Error: 型エラーが大量に出る
Cause: 型定義ファイルの破損、あるいは未完成の実装
Solution: エラー内容を要約してユーザーに共有し、修正方針を確認する
